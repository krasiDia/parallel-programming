## Эксперимент
  Для удобства я сгенерировала 2 файла: matrix_1 и matrix_2, в которых содержатся матрицы размером 2000*2000. И далее в ходе исследования я меняла только константу SIZE_MATRIX, причем исходные матрицы оставались без изменений. Это позволило мне не создавать дополнительные файлы с матрицами необходимых размеров. 
  
  Для каждого значения SIZE_MATRIX использовался верхний левый квадрат соответствующего размера исходных матриц. Время измерялось с помощью *omp_get_wtime()* только для участка программы, выполняющего умножение матриц.
  
  OpenMP создаёт несколько потоков, которые будут работать над одной задачей. Количество потоков задается через константную переменную NUM_STREAMS. Далее  OpenMP равномерно распределит итерации циклов между всеми потоками еще до их выполнения. 
  
  Ускорение рассчитывалось по формуле

$S_p = \frac{T_{\text{посл}}}{T_p},$

а эффективность — по формуле

$E_p = \frac{S_p}{p} \cdot 100%,$

где $T_{\text{посл}}$ — время последовательной версии, $T_p$ — время OpenMP-версии с $p$ потоками.

Эффективность показывает, насколько рационально используются вычислительные возможности потоков при параллельном выполнении программы. Если при увеличении количества потоков ускорение растёт, а эффективность снижается, это не обязательно означает, что программа работает хуже. Она может продолжать выполняться быстрее, однако каждый дополнительный поток приносит всё меньший прирост производительности.

Например, если при переходе с одного потока на два программа ускоряется в два раза, это соответствует идеальному распараллеливанию с эффективностью 100%. Если же при переходе с четырёх потоков на восемь время выполнения сокращается лишь незначительно, эффективность такого распараллеливания будет ниже: увеличение количества потоков не обеспечивает пропорционального роста производительности. Это может быть связано с накладными расходами на управление потоками, ограничениями аппаратных ресурсов и конкуренцией за доступ к памяти.

Ускорение показывает, во сколько раз параллельная версия быстрее последовательной. Значение выше 1 означает ускорение, а ниже 1 — что параллельная версия в данном измерении оказалась медленнее последовательной. Увеличение числа потоков не гарантирует пропорционального ускорения.

Эффективность учитывает число потоков, использованных для получения ускорения. При идеальном линейном ускорении она равна 100%. Значения выше 100% возможны в экспериментальных измерениях, если параллельная версия оказалась быстрее выбранной последовательной базы; это не следует интерпретировать как устойчивую сверхлинейную эффективность без повторных измерений.

## Вывод
В ходе лабораторной работы была исследована параллелизация умножения матриц с использованием OpenMP при размерах матриц от 200 × 200 до 2000 × 2000 и количестве потоков 1, 2, 4 и 8.

По полученным измерениям, увеличение числа потоков в большинстве случаев уменьшало время выполнения. Наибольшее ускорение среди приведённых результатов наблюдалось для матриц 2000 × 2000 при 8 потоках: примерно **5,02 раза** относительно последовательной версии. Время выполнения при этом снизилось с 162,73 с до 32,39 с.

Ускорение не было пропорционально числу потоков. Например, для матриц 400 × 400 время при 8 потоках оказалось немного больше, чем при 4 потоках (0,123 с против 0,118 с). Это показывает, что накладные расходы и особенности распределения вычислений могут нивелировать пользу от добавления потоков, особенно на сравнительно небольших задачах.

В отдельных опытах OpenMP-версия с одним потоком работала медленнее последовательной версии, например для размеров 400 × 400, 800 × 800, 1200 × 1200 и 2000 × 2000. Для размера 2000 × 2000 время при одном потоке составило 230,53 с против 162,73 с у последовательной версии. Такие различия могут быть связаны с тем, что OpenMP должен организовать параллельную область, распределить итерации цикла и выполнить служебные действия, соответсвенно, на это он тратит чуть больше времени чем последовательное выполнение программы. 

Эффективность для некоторых измерений превышает 100%, поскольку она рассчитывается относительно последовательного времени, а не относительно времени OpenMP-версии с одним потоком.

Таким образом, эксперимент показывает, что OpenMP позволяет существенно сократить время умножения больших матриц, однако оптимальное число потоков зависит от размера задачи и условий выполнения.
