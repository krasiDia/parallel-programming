# LAB 1
## Задание 
  Написать программу на языке C/C++ для перемножения двух квадратных матриц с обязательной автоматизированной верификацией результатов вычислений с помощью сторонних библиотек. Сравнить изменения времени выполнения от объема задачи
## Код решения 
### Структура проекта 
```text
ParallelProgramming/
│
├── matrix_1.txt - файл с первой матрицей
├── matrix_2.txt - файл со второй матрицей
├── matrix_result.txt - файл с матрицей-произведением
├── result.txt - файл с результатами замеров времени и объема 
│
├── lab1.cpp - код решения 
├── verify.py - верификация 
│
├── CMakeLists.txt
├── CMakePresets.json
└── README.md
```
  Решение задачи выполнено на языке C++ - **lab1.cpp**. Вычисление произведения двух матриц реализовано с помощью тройного цикла. 
  Для независимой проверки результата используется Python и библиотека NumPy. Программа **verify.py** считывает исходные матрицы и результат, полученный программой на C++, после чего самостоятельно вычисляет эталонный результат с помощью операции матричного умножения *A @ B*.

Полученный результат сравнивается с результатом C++ с помощью *numpy.array_equal()*. При полном совпадении выводится сообщение об успешной верификации.
## Эксперимент
  Для удобства я сгенерировала 2 файла: matrix_1 и matrix_2, в которых содержатся матрицы размером 2000*2000. И далее в ходе исследования я меняла только константу SIZE_MATRIX, причем исходные матрицы оставались без изменений. Это позволило мне не создавать дополнительные файлы с матрицами необходимых размером. 
  
  Для каждого значения SIZE_MATRIX использовался верхний левый квадрат соответствующего размера исходных матриц. Время измерялось с помощью *std::chrono* только для участка программы, выполняющего умножение матриц
  
  Объем вычислений производился по формуле: $$V=2N^3$$, где *N* - размеры матрицы. Умножаем на 2, так как производим 2 арифмитических операции

## Вывод
Из таблицы хорошо видно, что чем больше размерность матрицы, тем больше вычислительная нагрузка и тем больше время выполнения. 

При увеличении размера матрицы с 200 до 400 элементов объём вычислений увеличивается в 8 раз, а время выполнения — примерно в 7,1 раза. При увеличении размера с 400 до 800 объём также увеличивается в 8 раз, а время — примерно в 9,1 раза. С 800 до 1200 объем увеличился в 3,375 раз ($$1200/800=1.5$$ -> $$1.5^3=3.375$$), время увеличилось примерно в 13,1 раз.  

В целом наблюдается кубический характер роста вычислительной нагрузки, соответствующий теоретической сложности алгоритма $$O(N^3)$$.

Следует учитывать, что время выполнения может незначительно изменяться при повторных запусках программы из-за загрузки процессора, работы фоновых процессов и других факторов операционной системы.
