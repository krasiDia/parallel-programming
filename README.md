# LAB 3

## 1. Цель работы

Изучить принципы параллельного программирования с использованием технологии MPI (Message Passing Interface). Модифицировать программу последовательного умножения матриц из лабораторной работы №1 для параллельного выполнения. Исследовать зависимость времени выполнения программы от размера матриц и количества вычислительных процессов.

## 2. Теоретические сведения

**MPI (Message Passing Interface)** — стандарт передачи сообщений, предназначенный для организации взаимодействия между параллельными процессами. Каждый MPI-процесс имеет собственное адресное пространство и выполняет свою часть вычислений. Обмен данными между процессами осуществляется с помощью специальных функций MPI.

В отличие от OpenMP, где потоки могут совместно использовать общую память, MPI предполагает распределённую модель памяти: процессы не имеют прямого доступа к переменным друг друга.

Основные функции MPI, используемые в работе:

| Функция | Назначение |
|:---|:---|
| `MPI_Init` | Инициализация среды MPI |
| `MPI_Finalize` | Завершение работы MPI |
| `MPI_Comm_rank` | Получение номера текущего процесса (rank) |
| `MPI_Comm_size` | Получение общего количества процессов |
| `MPI_Scatter` | Распределение частей массива между процессами |
| `MPI_Bcast` | Передача одних и тех же данных всем процессам |
| `MPI_Gather` | Сбор результатов от всех процессов в один массив |
| `MPI_Barrier` | Синхронизация процессов |
| `MPI_Wtime` | Измерение времени выполнения |
| `MPI_Reduce` | Объединение значений, полученных от разных процессов |

## 3. Постановка задачи

Необходимо модифицировать программу последовательного умножения двух квадратных матриц из лабораторной работы №1 для параллельной работы с использованием MPI.

Результирующая матрица \(C\) определяется следующим образом:

\[
C=A\cdot B
\]

Каждый элемент результирующей матрицы вычисляется по формуле:

\[
C_{ij}=\sum_{k=0}^{N-1} A_{ik}\cdot B_{kj}
\]

Для ускорения вычислений необходимо распределить строки первой матрицы между несколькими MPI-процессами. Каждый процесс должен вычислить соответствующие строки результирующей матрицы, после чего результаты собираются в один массив.

Вычислительная сложность последовательного алгоритма составляет:

\[
O(N^3)
\]

## 4. Описание алгоритма

Для реализации параллельного умножения матриц используется следующий алгоритм.

**1. Инициализация MPI.**

В начале программы вызывается `MPI_Init`. Затем каждый процесс получает свой номер (`rank`) и общее количество процессов (`size`) с помощью функций `MPI_Comm_rank` и `MPI_Comm_size`.

**2. Проверка возможности распределения данных.**

Для равномерного распределения строк размер матрицы должен делиться на количество процессов без остатка. Поэтому перед началом вычислений выполняется проверка:

\[
N \bmod P=0
\]

где \(N\) — размер матрицы, а \(P\) — количество MPI-процессов.

**3. Подготовка данных.**

Нулевой процесс (rank 0) считывает исходные матрицы из файлов `matrix_1.txt` и `matrix_2.txt`.

Для упрощения вычислений вторая матрица транспонируется. Это позволяет обращаться к элементам её строк последовательно в памяти при вычислении скалярного произведения.

**4. Распределение данных.**

Первая матрица распределяется между процессами с помощью `MPI_Scatter`. Каждый процесс получает определённое количество строк первой матрицы.

Транспонированная вторая матрица передаётся всем процессам с помощью `MPI_Bcast`, поскольку для вычисления своей части результирующей матрицы каждому процессу необходима вся вторая матрица.

**5. Параллельные вычисления.**

Каждый процесс независимо вычисляет свою часть результирующей матрицы. Для этого используется стандартный алгоритм умножения матриц с тремя вложенными циклами.

**6. Сбор результатов.**

После завершения вычислений локальные части результирующей матрицы объединяются с помощью `MPI_Gather`. Итоговая матрица собирается на процессе с номером 0.

**7. Измерение времени и вывод результатов.**

Перед началом измерений процессы синхронизируются с помощью `MPI_Barrier`. Время фиксируется функцией `MPI_Wtime`.

После завершения вычислений каждый процесс определяет своё время выполнения. С помощью `MPI_Reduce` и операции `MPI_MAX` на нулевой процесс передаётся максимальное время среди всех процессов.

Нулевой процесс записывает результирующую матрицу в файл `matrix_result.txt`, а информацию о времени выполнения — в файл `result.txt`.

## 5. Распределение вычислений между процессами

Для распределения строк используется равномерное разбиение матрицы.

Количество строк, обрабатываемых одним процессом:

\[
R=\frac{N}{P}
\]

Количество элементов, передаваемых каждому процессу:

\[
E=\frac{N^2}{P}
\]

где:
- \(N\) — размер матрицы;
- \(P\) — количество MPI-процессов;
- \(R\) — количество строк, приходящихся на один процесс;
- \(E\) — количество элементов локальной части матрицы.

Например, при размере матрицы \(8\times8\) и использовании четырёх процессов каждый процесс получает две строки первой матрицы.

| Процесс | Rank | Вычисляемые строки матрицы A |
|:---:|:---:|:---:|
| Процесс 1 | 0 | 0–1 |
| Процесс 2 | 1 | 2–3 |
| Процесс 3 | 2 | 4–5 |
| Процесс 4 | 3 | 6–7 |

Каждый процесс получает свою часть первой матрицы, но полную транспонированную вторую матрицу. Благодаря этому процессы могут выполнять вычисления независимо друг от друга.

## 6. Проведение экспериментов

Для исследования производительности параллельной программы необходимо провести серию экспериментов с различными размерами матриц и количеством MPI-процессов.

Эксперименты проводятся на одном вычислительном узле суперкомпьютера. Количество MPI-процессов изменяется с помощью планировщика Slurm.

Для исследования используются следующие параметры:

- Размеры матриц: 200, 400, 800, 1200, 1600 и 2000.
- Количество MPI-процессов: 1, 2, 4 и 8.
- Для каждого набора параметров измеряется время выполнения программы.

Для запуска программы используется команда `mpirun`, а количество процессов задаётся параметрами задания Slurm (`--ntasks` и `--ntasks-per-node`).

В ходе эксперимента измеряется время выполнения этапов распределения данных, параллельного умножения матриц и сбора результатов. Чтение исходных файлов и запись результата в измеряемый интервал не входят.

Для оценки производительности MPI-версии результаты сравниваются со временем выполнения последовательной программы из лабораторной работы №1.

### 6.1. Расчёт ускорения и эффективности

Для оценки эффективности параллельной программы используются следующие показатели.

**Ускорение (Speedup):**

\[
S_P=\frac{T_{\text{посл}}}{T_P}
\]

где:
- \(T_{\text{посл}}\) — время выполнения последовательной версии программы;
- \(T_P\) — время выполнения MPI-версии с \(P\) процессами.

Ускорение показывает, во сколько раз параллельная программа работает быстрее по сравнению с последовательной версией.

**Эффективность (Efficiency):**

\[
E_P=\frac{S_P}{P}\cdot100\%
\]

Эффективность показывает, насколько рационально используются вычислительные ресурсы при параллельном выполнении программы.

При идеальном линейном ускорении эффективность составляет 100%. На практике эффективность может снижаться из-за затрат на передачу данных между процессами, синхронизацию и распределение вычислений.

## 8. Вывод

В ходе лабораторной работы была модифицирована программа последовательного умножения матриц из лабораторной работы №1 для параллельного выполнения с использованием технологии MPI.

Был реализован алгоритм распределения строк первой матрицы между процессами с помощью `MPI_Scatter`, передачи транспонированной второй матрицы с помощью `MPI_Bcast` и сбора локальных результатов с помощью `MPI_Gather`.

Для оценки производительности программы были предусмотрены эксперименты с различными размерами матриц и количеством MPI-процессов. Время выполнения измеряется с учётом распределения данных, вычислений и сбора результатов.

По результатам экспериментов необходимо оценить влияние размера матриц и количества процессов на время выполнения, ускорение и эффективность параллельной программы.

Особое внимание следует уделить сравнению MPI-версии с последовательной реализацией из лабораторной работы №1, а также анализу накладных расходов, связанных с обменом сообщениями и синхронизацией процессов.

Таким образом, лабораторная работа позволяет изучить принципы распределённой модели памяти и оценить возможности технологии MPI для ускорения вычислительно сложных задач.
